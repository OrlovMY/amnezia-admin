# amnezia-admin

Утилита администрирования сервера [Amnezia VPN](https://amnezia.org/) (AmneziaWG / WireGuard) через SSH.
Работает по административному ключу `vpn://…`, внутри которого — SSH-доступ к серверу.
Есть графическая версия (GUI на [Fyne](https://fyne.io/)) и консольная (CLI).

## Возможности

- Список пользователей: имя, дата создания, последняя активность, объём трафика.
- Сортировка по любой колонке (с запоминанием выбора).
- Создание пользователя с выдачей конфига и QR-кода.
- Переименование, временное отключение/включение без удаления, удаление.
- Перевыпуск конфига (re-key) — на случай утери или смены устройства.
- Локальное шифрованное хранилище ключей `vpn://` с доступом по пин-коду
  (Argon2id + XChaCha20-Poly1305, опциональная привязка к учётной записи Windows через DPAPI).

## Сборка

Требуется Go 1.21+. Для GUI нужен C-компилятор (CGO) — например MinGW-w64 на Windows.

```sh
# CLI (без CGO)
go build -o amnezia-admin.exe ./cmd/cli

# GUI (нужен CGO + gcc в PATH)
CGO_ENABLED=1 go build -ldflags "-s -w -H windowsgui" -o amnezia-admin-gui.exe ./cmd/gui
```

## Использование

Запустите GUI (`amnezia-admin-gui.exe`) и вставьте административный ключ `vpn://…`,
либо CLI:

```sh
amnezia-admin.exe list   -key vpn://...
amnezia-admin.exe add    -key vpn://... -name "Иван Иванов"
amnezia-admin.exe rename -key vpn://... -name "Иван Иванов" -newname "Иван Петров"
amnezia-admin.exe toggle -key vpn://... -name "Иван Иванов"
amnezia-admin.exe rekey  -key vpn://... -name "Иван Иванов"
amnezia-admin.exe del    -key vpn://... -name "Иван Иванов"
```

Ключ можно передать через переменную окружения `AMNEZIA_KEY`.

## Проверка на живом сервере (выполняет владелец)

После обновления, перед тем как что-либо создавать/удалять/менять — открыть
список пользователей: он обязан совпадать с прежним по составу (столько же
записей, те же имена).

Если утилита сообщает об **ошибке чтения `clientsTable`** — это новое
(с этого обновления) поведение вместо прежнего "показать пустой список".
Раньше сбой чтения (нет прав, контейнер перезапускается и т.п.) тихо
превращался в пустой список пользователей, и создание нового пользователя
поверх этого стирало всех существующих. Теперь такой сбой — явная ошибка.
**В этом случае ничего не создавать и не удалять до выяснения причины** —
устранить причину ошибки (права, состояние контейнера) и повторить.

### Проверка транзакции (PR-2) на канарейке

Каждая мутация (`add`/`del`/`rename`/`toggle`/`rekey`) теперь — транзакция:
сначала можно посмотреть, что изменится, ничего не записывая (`-dry-run` в
CLI, кнопка «Показать изменения» в диалогах GUI), и только потом применить.
Порядок проверки на живом сервере:

1. `amnezia-admin.exe add -dry-run -key <ключ> -name Канарейка` — должен
   вывести diff `wg0.conf`/`clientsTable` и строку `Ничего не записано
   (dry-run).`, ничего не создавая. Список пользователей (`list`) не
   изменился.
2. `amnezia-admin.exe add -key <ключ> -name Канарейка` — реально создаёт
   пользователя; список пользователей теперь содержит "Канарейка" и всех
   прежних.
3. Подключиться устройством-канарейкой по выданному конфигу, убедиться, что
   VPN поднимается.
4. `amnezia-admin.exe del -dry-run -key <ключ> -name Канарейка` — diff и
   `Ничего не записано (dry-run).`, пользователь "Канарейка" всё ещё в списке.
5. `amnezia-admin.exe del -key <ключ> -name Канарейка` — реально удаляет.
   Список пользователей вернулся к исходному составу (без "Канарейка").

После **каждого** шага 1–5 — список пользователей (`list`) сверяется с
ожидаемым составом, а у существующих (не канареечных) пользователей
соединение не прерывалось (переспросить владельца/проверить с их стороны).
Выполняет это исключительно владелец сервера — агент такие команды против
реального сервера не запускает.

## Безопасность

Административный ключ `vpn://…` даёт полный SSH-доступ к серверу — храните его как секрет.
Локальное хранилище защищает ключ пин-кодом; для утекшего файла реальную стойкость
обеспечивают длина пин-кода и параметры Argon2id, а привязка к учётной записи Windows (DPAPI)
делает файл бесполезным на другом компьютере. Управление пользователями поддержано для
протоколов семейства WireGuard/AmneziaWG.
