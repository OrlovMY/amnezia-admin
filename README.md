# amnezia-admin

Утилита администрирования сервера [Amnezia VPN](https://amnezia.org/) (AmneziaWG / WireGuard) через SSH.
Работает по административному ключу `vpn://…`, внутри которого — SSH-доступ к серверу.
Есть графическая версия (GUI на [Fyne](https://fyne.io/)) и консольная (CLI).

## Возможности

- Список пользователей: имя, дата создания, последняя активность, объём трафика.
- Сортировка по любой колонке (с запоминанием выбора).
- Создание пользователя с выдачей конфига и QR-кода.
- Переименование, временное отключение/включение без удаления, удаление.
- Перевыпуск конфига (re-key) — на случай утери или смены устройства.
- Локальное шифрованное хранилище ключей `vpn://` с доступом по пин-коду
  (Argon2id + XChaCha20-Poly1305, опциональная привязка к учётной записи Windows через DPAPI).

## Сборка

Требуется Go 1.21+. Для GUI нужен C-компилятор (CGO) — например MinGW-w64 на Windows.

```sh
# CLI (без CGO)
go build -o amnezia-admin.exe ./cmd/cli

# GUI (нужен CGO + gcc в PATH)
CGO_ENABLED=1 go build -ldflags "-s -w -H windowsgui" -o amnezia-admin-gui.exe ./cmd/gui
```

## Использование

Запустите GUI (`amnezia-admin-gui.exe`) и вставьте административный ключ `vpn://…`,
либо CLI:

```sh
amnezia-admin.exe list   -key vpn://...
amnezia-admin.exe add    -key vpn://... -name "Иван Иванов"
amnezia-admin.exe rename -key vpn://... -name "Иван Иванов" -newname "Иван Петров"
amnezia-admin.exe toggle -key vpn://... -name "Иван Иванов"
amnezia-admin.exe rekey  -key vpn://... -name "Иван Иванов"
amnezia-admin.exe del    -key vpn://... -name "Иван Иванов"
```

Ключ можно передать через переменную окружения `AMNEZIA_KEY`.

### Подтверждение необратимых действий (`del`, `rekey`, `toggle`-отключение)

`del`, `rekey` и `toggle`, когда он отключает активного пользователя,
необратимы — перед выполнением утилита печатает карточку (сервер, контейнер,
имя, дата создания, последнее подключение, публичный ключ) и спрашивает
подтверждение `(y/n)`, если запущена у терминала. `add`, `rename` и `toggle`,
когда он включает отключённого, — без вопроса, как и раньше.

Для скриптов — флаг `-yes` (без него, без терминала — отказ):

```sh
amnezia-admin.exe del -yes -key vpn://... -name "Иван Иванов"
```

**`-yes` — только для проверенных скриптов**: он пропускает вопрос
целиком, полагаясь только на то, что вызывающий скрипт сам уверен в
действии (например, в правильности имени). `-yes` нельзя задать через
переменную окружения — только флагом, явно на каждый запуск.

Коды возврата CLI:

| Код | Значение |
|---|---|
| `0` | успех |
| `1` | ошибка (SSH, декодирование ключа, сервер вернул ошибку и т.п.) |
| `2` | отказ из-за отсутствия подтверждения — нет терминала и нет `-yes`, либо явный ответ `n` у терминала |

`-dry-run` побеждает `-yes` и вопрос: при `-dry-run` печатается план
изменений, ничего не пишется на сервер, и подтверждение не запрашивается.

### Ключ сервера

Первое подключение к серверу утилита проверяет по отпечатку SSH-ключа хоста —
TOFU (trust-on-first-use), как у OpenSSH: показывает отпечаток и спрашивает
подтверждение (GUI — диалог «Неизвестный сервер»; CLI у терминала — вопрос
`(y/n)`), затем запоминает его в файле `known_hosts` рядом с каталогом
"Настройки" (там же, где хранилище `.avlt`). Повторное подключение к уже
известному серверу — тихо, без вопроса.

Если ключ сервера **изменился** — подключение отклоняется ВСЕГДА, без
исключений: кнопки или флага «всё равно подключиться» нет и не будет (решение
владельца, 2026-09-14). Восстановление доступа:

- **GUI, ключ открыт из сохранённого хранилища.** Диалог «Ключ сервера
  изменился» предлагает «Забыть ключ сервера…» — второй, отдельный диалог
  подтверждения стирает отпечаток и в хранилище (`.avlt`), и в `known_hosts`;
  само подключение при этом НЕ устанавливается. При следующем «Подключиться»
  вы увидите новый отпечаток и подтвердите его заново — как для нового
  сервера. Делайте это, только если сами переустанавливали сервер: если нет —
  возможна подмена, не подключайтесь.
- **GUI с ключом, введённым вручную, и CLI** (у него хранилища нет вовсе):
  кнопки «забыть» нет — единственный путь восстановления доступа после
  легитимной переустановки сервера: вручную удалить строку с адресом сервера
  из файла `known_hosts` (точный путь и строка — в тексте ошибки) и
  подключиться заново.

Скриптам без терминала (`cron`, CI) для подключения к **новому** серверу
нужен явный отпечаток — флаг `-hostkey SHA256:…` (значение — из первого
ручного подключения, либо прямо с сервера: `ssh-keygen -lf
/etc/ssh/ssh_host_ed25519_key.pub`). Без `-hostkey` подключение к неизвестному
серверу без терминала отклоняется с кодом `2` и печатает отпечаток на
`stderr` — его можно прочитать и передать `-hostkey` следующим запуском.
`-hostkey` **не обходит** проверку смены ключа: если сервер уже известен
(есть запись в `known_hosts`) и предъявляет ДРУГОЙ ключ — отказ всегда, даже
если `-hostkey` совпадает с новым (только что предъявленным) отпечатком.

## Проверка на живом сервере (выполняет владелец)

После обновления, перед тем как что-либо создавать/удалять/менять — открыть
список пользователей: он обязан совпадать с прежним по составу (столько же
записей, те же имена).

Если утилита сообщает об **ошибке чтения `clientsTable`** — это новое
(с этого обновления) поведение вместо прежнего "показать пустой список".
Раньше сбой чтения (нет прав, контейнер перезапускается и т.п.) тихо
превращался в пустой список пользователей, и создание нового пользователя
поверх этого стирало всех существующих. Теперь такой сбой — явная ошибка.
**В этом случае ничего не создавать и не удалять до выяснения причины** —
устранить причину ошибки (права, состояние контейнера) и повторить.

### Проверка транзакции (PR-2) на канарейке

Каждая мутация (`add`/`del`/`rename`/`toggle`/`rekey`) теперь — транзакция:
сначала можно посмотреть, что изменится, ничего не записывая (`-dry-run` в
CLI, кнопка «Показать изменения» в диалогах GUI), и только потом применить.
Порядок проверки на живом сервере:

1. `amnezia-admin.exe add -dry-run -key <ключ> -name Канарейка` — должен
   вывести diff `wg0.conf`/`clientsTable` и строку `Ничего не записано
   (dry-run).`, ничего не создавая. Список пользователей (`list`) не
   изменился.
2. `amnezia-admin.exe add -key <ключ> -name Канарейка` — реально создаёт
   пользователя; список пользователей теперь содержит "Канарейка" и всех
   прежних.
3. Подключиться устройством-канарейкой по выданному конфигу, убедиться, что
   VPN поднимается.
4. `amnezia-admin.exe del -dry-run -key <ключ> -name Канарейка` — diff и
   `Ничего не записано (dry-run).`, пользователь "Канарейка" всё ещё в списке.
5. `amnezia-admin.exe del -key <ключ> -name Канарейка` — реально удаляет.
   Список пользователей вернулся к исходному составу (без "Канарейка").

После **каждого** шага 1–5 — список пользователей (`list`) сверяется с
ожидаемым составом, а у существующих (не канареечных) пользователей
соединение не прерывалось (переспросить владельца/проверить с их стороны).
Выполняет это исключительно владелец сервера — агент такие команды против
реального сервера не запускает.

### Проверка резерва IP отключённых (PR-3) на канарейке

IP пользователя теперь постоянен: отключение резервирует его адрес — этот
адрес не выдаётся никому другому, пока пользователь не удалён; включение при
занятом резервном адресе — отказ с именем того, кто его занял; перевыпуск
конфига (`rekey`) сохраняет адрес и отказывает отключённому пользователю
("сначала включите"). Порядок проверки на живом сервере:

1. Отключить канарейку (`toggle`) — она пропадает из активных peer'ов, её IP
   никому не отдан.
2. Создать второго (не канареечного) пользователя — убедиться, что у него
   **другой** IP, не тот, что был у канарейки.
3. Включить канарейку обратно (`toggle`) — убедиться, что ей вернулся
   **её прежний** IP (тот же, что был до отключения), и что VPN с её стороны
   снова поднимается.
4. Перевыпустить конфиг канарейке (`rekey`) — убедиться, что новый конфиг
   выдан с **тем же** IP, что и раньше (ключи новые, адрес прежний).
5. Отключить канарейку ещё раз и попробовать перевыпустить ей конфиг
   (`rekey`) — ожидается отказ с текстом «сначала включите», без записи.

Как и для проверки транзакции выше — после каждого шага сверяется список
пользователей и то, что соединения существующих (не канареечных)
пользователей не прерывались. Выполняет это исключительно владелец сервера.

### Проверка подтверждения необратимых команд (PR-5) на канарейке

1. `echo | amnezia-admin.exe del -key <ключ> -name Канарейка` (пустой stdin —
   без терминала) — ожидается отказ, код возврата `2`, канарейка всё ещё в
   списке (`list`).
2. `amnezia-admin.exe del -key <ключ> -name Канарейка`, запущено прямо в
   терминале — ожидается карточка с сервером/контейнером/именем/датой
   создания/последним подключением/ключом, на вопрос ответить `n` —
   ожидается `Отменено.`, код возврата `2`, канарейка всё ещё в списке.
3. `amnezia-admin.exe toggle -key <ключ> -name Канарейка` над активной
   канарейкой — ожидается тот же вопрос/карточка (действие «отключить»).
4. `amnezia-admin.exe toggle -key <ключ> -name Канарейка` над уже
   отключённой канарейкой (включение) — выполняется сразу, без вопроса и
   без карточки (подкоманда `toggle` при включении вопроса не задаёт — ни
   сейчас, ни до PR-5; вопрос при включении есть только в интерактивном
   меню, не в этой подкоманде).
5. `amnezia-admin.exe del -yes -key <ключ> -name Канарейка` — удаляет без
   вопроса (карточка печатается для журнала), код возврата `0`.

Выполняет это исключительно владелец сервера — агент такие команды против
реального сервера не запускает.

### Проверка ключа хоста (PR-4) на живом сервере

Выполняет исключительно владелец сервера — агент к реальному серверу не
подключается (см. «Проверка без сервера (QA)» ниже — то же самое проверяется
на `cmd/fakeserver`).

1. Первое подключение к серверу после этого обновления — утилита покажет
   отпечаток ключа хоста (GUI: диалог «Неизвестный сервер»; CLI у терминала:
   вопрос `(y/n)`). Сверить с тем, что показывает сам сервер:
   `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` (или
   `ssh_host_ecdsa_key.pub` / `ssh_host_rsa_key.pub` — какой ключ сервер
   реально использует). Совпал — подтвердить.
2. Второе подключение тем же способом (GUI с тем же сохранённым ключом, CLI
   с тем же `-key`) — без вопроса, тихо: адрес уже в `known_hosts`.
3. Открытие СТАРОГО (сохранённого до этого обновления) ключа в GUI —
   по-прежнему работает (формат хранилища v1 читается без изменений); после
   первого успешного подключения файл `.avlt` перезаписывается (обновится
   дата изменения) — в него допишется отпечаток ключа хоста, второй раз
   вопрос про этот сервер GUI не покажет.
4. Скрипт без терминала (`cron`, CI) без `-hostkey` против ЭТОГО сервера в
   первый раз — отказ с кодом `2` и отпечатком на `stderr` (см. «Ключ
   сервера» выше).

### Проверка без сервера (QA) — фейковый SSH-сервер (PR-4)

Владелец сказал прямо: «тестового сервера нет». Проверять диалог о ключе
хоста (PR-4: TOFU-подтверждение неизвестного сервера, жёсткий отказ при
смене ключа) на реальном сервере поэтому нельзя. Для этого есть
`cmd/fakeserver` — отдельный локальный бинарь (только на `127.0.0.1`,
**не входит в релизную сборку**, никогда не подключается к боевым
серверам): настоящий SSH-сервер с ключом хоста, который "исполняет" те же
самые команды `docker`/`wg`, что и обычный фейк для юнит-тестов.

```sh
go run ./cmd/fakeserver                          # порт 2222, новый ключ хоста при каждом запуске
go run ./cmd/fakeserver -hostkey-file key.bin     # ключ хоста сохраняется в key.bin и переиспользуется
```

Сервер печатает адрес, отпечаток ключа хоста (`SHA256:…`) и готовый ключ
`vpn://…` — его нужно вставить в поле подключения (GUI) или передать через
`-key`/`AMNEZIA_KEY` (CLI).

Сценарии проверки:

1. **Неизвестный сервер.** Первое подключение свежим `vpn://` ключом от
   `cmd/fakeserver` — должен появиться вопрос с отпечатком ключа хоста;
   сверить его с тем, что напечатал `cmd/fakeserver` в терминале.
2. **Известный сервер.** Повторное подключение тем же ключом — без
   вопроса, тихо.
3. **Ключ сервера изменился.** Остановить `cmd/fakeserver` (Ctrl+C) и
   запустить снова с `-hostkey-file <файл> -new-hostkey` на том же `-port`
   (тот же адрес, новый ключ хоста) — подключение тем же сохранённым
   `vpn://` ключом должно быть отклонено с сообщением о смене ключа;
   кнопки «всё равно подключиться» на этом экране нет и не будет.

Сценарии 1–3 проходятся полностью через `amnezia-admin.exe`/
`amnezia-admin-gui.exe` против `cmd/fakeserver` (диалоги GUI, вопрос в
терминале CLI и флаг `-hostkey` — часть Б этого PR). Дополнительно для QA-02:

4. **CLI без терминала.** `echo | amnezia-admin.exe list -key <ключ от
   cmd/fakeserver>` (пустой stdin) на НЕИЗВЕСТНЫЙ сервер — отказ, код `2`,
   отпечаток ключа и подсказка `-hostkey SHA256:…` на `stderr`, ничего не
   выводится в `stdout`. С верным `-hostkey` — подключается и печатает
   таблицу пользователей без вопроса; `known_hosts` рядом с "Настройки"
   получает одну строку с адресом `cmd/fakeserver`.
5. **Хранилище v1 → v2 (GUI).** Сохранить ключ от `cmd/fakeserver` (без
   привязки к машине — так проще проверять на любом ПК), подтвердить
   неизвестный сервер — файл `.avlt` допишет отпечаток при первом
   подключении (дата изменения файла обновится). Закрыть приложение,
   открыть ключ заново — вопрос про сервер второй раз не появится.
6. **«Забыть ключ сервера» (GUI, R2).** Открыть сохранённый ключ (сценарий
   5), затем переустановить `cmd/fakeserver` с `-new-hostkey` на том же
   `-port` и подключиться из хранилища — появится диалог «Ключ сервера
   изменился» с кнопкой «Забыть ключ сервера…»; после подтверждения (второй,
   отдельный диалог) — возврат на экран подключения со статусом «Ключ
   сервера забыт. Нажмите «Подключиться»…»; само подключение в этот момент
   НЕ устанавливается. Открыть тот же сохранённый ключ ещё раз —
   подключение идёт обычным путём неизвестного сервера (новый отпечаток,
   вопрос «Доверять и запомнить»). Кнопки «всё равно подключиться» нигде на
   этом пути нет.

## Безопасность

Административный ключ `vpn://…` даёт полный SSH-доступ к серверу — храните его как секрет.
Локальное хранилище защищает ключ пин-кодом; для утекшего файла реальную стойкость
обеспечивают длина пин-кода и параметры Argon2id, а привязка к учётной записи Windows (DPAPI)
делает файл бесполезным на другом компьютере. Управление пользователями поддержано для
протоколов семейства WireGuard/AmneziaWG.
