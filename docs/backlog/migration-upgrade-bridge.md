# БЭКЛОГ: обновление версии протокола при переезде («переходный мост»)

Статус: **идея, не в работе.** Решение владельца 02.10.2026: в программу бэкапа
входит только переезд; обновление версии и мосты — отложены. Возможно, это
отдельное приложение, а не часть amnezia-admin.

## Задача

При переезде на сервер, где протокол новее (например, старый AmneziaWG → AWG3),
старые конфиги пользователей к новому серверу не подключатся: другие параметры
маскировки. Приватных ключей клиентов у нас нет — без перевыпуска не обойтись.
Хочется, чтобы пользователь получил новый конфиг сам, без рассылки QR вручную.

## Идея «переходного моста»

1. На новом сервере временно поднимается старая версия протокола с перенесёнными
   ключом сервера, параметрами и пользователями — старые конфиги работают.
2. Рядом — новая версия.
3. Подключившийся по старому конфигу получает страницу со СВОИМ новым QR
   (личность — по адресу внутри туннеля).
4. Учёт: кто забрал новый конфиг; старая версия выключается, когда забрали все
   или по решению админа.

## Автоматическое открытие страницы

- Как портал Wi-Fi (captive portal): **НЕ ПРОВЕРЕНО**, срабатывает ли проверка
  сети Android/iOS через VPN-туннель. Проверить на тестовом сервере с телефоном
  до любого проектирования.
- Запасной путь — «интернет только через портал»: DNS/HTTP старых пользователей
  ведут на страницу; https даст ошибку сертификата → нужен простой http-адрес;
  мягкий период N дней, когда интернет ещё работает.

## Ограничения

- Мост работает, только если в старых конфигах endpoint — домен, или IP
  переносится на новый сервер.
- Пользователь всё равно один раз импортирует новый конфиг.

## В основной программе (не бэклог)

Переезд сравнивает протокол и версию источника и цели: совпадает — переносим;
не совпадает или не определено — СТОП до переезда с объяснением.
